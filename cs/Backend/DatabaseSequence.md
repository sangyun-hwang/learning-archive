# DB Sequence

## 개념

DB Sequence는 데이터베이스에서 고유한 숫자 값을 생성하기 위한 객체다.

주로 테이블의 primary key나 비즈니스 식별자 생성을 위해 사용한다.

```sql
CREATE SEQUENCE user_seq START WITH 1 INCREMENT BY 1;
```

값을 가져올 때마다 sequence는 다음 값을 반환한다.

```sql
SELECT nextval('user_seq');
```

```txt
1
2
3
4
```

Sequence는 특정 테이블 컬럼 자체라기보다, DB가 관리하는 숫자 생성기라고 볼 수 있다.

## Sequence의 목적

Sequence의 핵심 목적은 연속적인 번호를 빈틈없이 만드는 것이 아니라, 중복 없는 값을 안정적으로 생성하는 것이다.

```txt
끊김 없는 번호 생성기 X
중복 없는 번호 생성기 O
```

서버가 여러 대이거나 여러 트랜잭션이 동시에 실행되는 환경에서도 sequence는 고유한 값을 발급할 수 있다.

## Rollback되어도 값이 되돌아가지 않는 이유

Sequence 값은 보통 트랜잭션 rollback과 별개로 소비된다.

예를 들어 다음 흐름을 보자.

```txt
1. nextval -> 1
2. insert 수행
3. transaction rollback
4. nextval -> 2
```

이 경우 실제 테이블에는 id `1`을 가진 row가 없을 수 있다. 하지만 다음 sequence 값은 `2`가 된다.

이렇게 동작하는 이유는 sequence가 연속성보다 고유성을 우선하기 때문이다.

만약 rollback이 발생할 때마다 sequence 값을 되돌리려 하면, 동시에 실행 중인 다른 트랜잭션과 충돌할 수 있다. 분산 환경이나 동시성 환경에서는 중복 없는 값을 빠르게 발급하는 것이 더 중요하다.

## Gap이 생겨도 문제가 아닐 수 있는 이유

Sequence에서 중간 번호가 비어도 일반적으로 문제가 되지 않는다.

예를 들어 primary key의 목적은 row를 고유하게 식별하는 것이다.

```txt
id: 1
id: 2
id: 4
```

여기서 `3`이 비어 있어도 각 row를 식별하는 데 문제가 없다.

Sequence는 연속적인 번호표보다 고유한 식별자에 가깝다.

## Sequence와 Auto Increment

DBMS에 따라 sequence를 직접 생성하거나, auto increment 또는 identity column을 사용해 자동 증가 값을 만들 수 있다.

개념적으로는 모두 고유한 증가 값을 생성하기 위한 방식이다.

예시:

```sql
CREATE TABLE users (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name VARCHAR(100)
);
```

DBMS에 따라 내부 구현과 문법은 다르지만, 핵심은 DB가 id 값을 생성해 중복을 방지한다는 것이다.

## 여러 서버에서 유용한 이유

애플리케이션 서버가 여러 대일 때 각 서버가 직접 번호를 만들면 중복 위험이 생길 수 있다.

Sequence를 DB가 중앙에서 관리하면 여러 서버가 동시에 요청하더라도 고유한 값을 발급할 수 있다.

```txt
server A -> nextval -> 10
server B -> nextval -> 11
server C -> nextval -> 12
```

이 때문에 sequence는 동시성 환경에서 고유 id를 생성하는 데 유용하다.

## 주의할 점

### 연속 번호가 필요한 곳에는 부적합할 수 있음

세금계산서 번호처럼 법적, 회계적으로 끊김 없는 번호가 필요한 경우 sequence만으로는 요구사항을 만족하지 못할 수 있다.

sequence는 rollback, cache, 장애 상황에서 gap이 생길 수 있기 때문이다.

### 비즈니스 의미를 부여하지 않기

primary key id는 식별자일 뿐이다. `id` 값의 크기나 연속성에 비즈니스 의미를 과하게 부여하면 gap이 생겼을 때 문제가 된다.

### Sequence cache

일부 DB는 성능을 위해 sequence 값을 미리 cache할 수 있다. 이 경우 DB 재시작이나 장애 시 사용하지 않은 cache 값이 사라져 더 큰 gap이 생길 수 있다.

## 정리

DB Sequence는 중복 없는 숫자 값을 생성하기 위한 DB 객체다.

rollback되어도 sequence 값은 보통 되돌아가지 않으며, 이 때문에 중간 번호가 비어 있을 수 있다.

Sequence는 연속성보다 고유성을 우선하는 기능으로 이해해야 한다.
