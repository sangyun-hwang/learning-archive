# 리스트 가상화 (List Virtualization)

## 개념

리스트 가상화는 긴 목록 중 현재 화면에 필요한 항목과 주변 일부만 렌더링하는 기법이다. Windowing이라고도 부른다. 스크롤에 따라 렌더링 범위를 바꾸어 DOM 수와 렌더링 비용을 줄인다.

데이터 1만 개를 이미 받아 놓았다면 가상화 이후에도 그 데이터는 메모리에 그대로 있을 수 있다. 가상화가 데이터 전송량이나 저장된 데이터의 양까지 자동으로 줄여 주는 것은 아니다.

## 스크롤 길이를 유지하는 원리

전체 목록 크기에 해당하는 컨테이너나 여백을 만들고, 필요한 항목만 원래 목록에서의 위치에 배치한다. 항목 높이가 고정된 경우를 예로 들면 다음과 같다.

```text
전체 항목 수: 10,000개
항목 높이: 40px
전체 스크롤 공간: 400,000px

스크롤 위치: 4,000px
화면 높이: 400px
-> 대략 index 100~109가 화면에 들어옴
-> 필요한 항목만 해당 위치에 렌더링
```

실제 항목 DOM을 전부 만들지 않아도 전체 높이는 유지되므로 목록 끝까지 스크롤할 수 있다. 항목 높이가 가변적이면 추정치와 실제 측정값으로 전체 높이와 배치를 갱신한다.

TanStack Virtual의 예제도 전체 크기를 가진 내부 컨테이너와 표시할 항목의 위치를 계산하는 방식을 사용한다. [공식 소개와 예제](https://tanstack.com/virtual/latest/docs/introduction)

## Overscan

화면에 보이는 항목만 정확히 렌더링하면 빠른 스크롤에서 새 항목이 준비되기 전 빈 영역이 보일 수 있다. 이를 줄이기 위해 앞뒤 항목을 조금 더 렌더링하는 것이 overscan이다.

너무 적으면 빠른 스크롤에서 빈 영역이 나타날 수 있고, 너무 많으면 DOM과 렌더링 비용이 늘어난다. 항목의 복잡도와 실제 스크롤 동작을 보고 조정한다.

## 무한 스크롤과의 차이

| 방식 | 담당하는 문제 |
| --- | --- |
| 페이지네이션 | 어느 페이지의 데이터를 가져와 보여줄지 |
| 무한 스크롤 | 언제 다음 데이터를 추가로 가져올지 |
| 리스트 가상화 | 가져온 데이터 중 어떤 항목을 렌더링할지 |

무한 스크롤로 데이터를 계속 추가하면서 모든 항목을 DOM에 쌓으면 화면이 점점 무거워질 수 있다. 가상화를 함께 적용하면 데이터 조회는 이어가면서 렌더링 범위는 제한할 수 있다.

## React에서 상태를 유지할 때

화면 밖으로 나간 행이 언마운트되면 해당 컴포넌트의 로컬 state가 사라질 수 있다. 입력값이나 선택 상태를 유지해야 한다면 항목 ID를 기준으로 공통 부모나 Store 등에서 관리한다.

```text
상위 상태:
  draftsById['item-42'] = '작성 중인 내용'

item-42 행이 화면 밖으로 나가 언마운트
-> 상위에 입력값 유지
-> 다시 표시할 때 같은 ID의 값 전달
```

정렬이나 삽입으로 index가 달라질 수 있으므로 데이터의 고유 ID를 사용한다. 안정적인 key는 항목을 식별하는 데 도움이 되지만 언마운트된 컴포넌트의 로컬 state를 자동으로 보존해 주지는 않는다.

## 적용할 때 고려할 점

- 채팅처럼 높이가 다른 항목은 크기 측정과 위치 보정이 필요하다.
- 항목을 제거하는 구조에서는 키보드 포커스와 접근성을 함께 확인한다.
- DOM에 없는 내용은 브라우저 기본 페이지 내 검색 등에서 제약이 생길 수 있다.
- 작은 목록은 가상화 없이도 충분할 수 있다. 실제 항목 수와 성능을 보고 적용한다.

React의 Virtual DOM과도 구분한다. Virtual DOM은 UI 변경을 계산하는 표현이고, 리스트 가상화는 실제 렌더링할 목록의 범위를 제한하는 기법이다.

## 면접용 설명

리스트 가상화는 긴 목록에서 화면에 보이는 항목과 주변 일부만 렌더링해 DOM 수와 렌더링 비용을 줄이는 기법입니다. 전체 목록 높이는 컨테이너나 여백으로 유지하고 스크롤 위치에 따라 표시할 항목을 바꿉니다. 무한 스크롤은 데이터를 추가로 가져오는 시점을 다루므로 가상화와 함께 사용할 수 있습니다. 가변 높이와 언마운트되는 행의 입력 상태를 고려해야 합니다.
