# 편집기의 Undo / Redo

## 개념

Undo는 편집 내용을 이전 상태로 되돌리고 Redo는 되돌린 작업을 다시 적용한다. 브라우저 뒤로·앞으로 가기가 방문 기록을 이동하는 것과 달리, 편집기의 데이터 상태를 변경하는 기능이다.

간단한 선형 이력은 과거 past, 현재 present, 다시 적용할 future로 나누어 구현할 수 있다. 화면에는 present를 표시한다. Redux 전용 방식은 아니며 일반 JavaScript나 React useReducer 등으로도 구현할 수 있다. [Redux: Undo History](https://redux.js.org/usage/implementing-undo-history)

## 상태가 이동하는 원리

A, AB, ABC 순서로 입력했다고 가정한다.

```js
const history = {
  past: ['', 'A', 'AB'],
  present: 'ABC',
  future: [],
};
```

Undo에서는 past의 마지막 값을 present로 가져오고, 기존 present는 future의 앞에 보관한다.

```js
// Undo 후
{
  past: ['', 'A'],
  present: 'AB',
  future: ['ABC'],
}
```

Redo에서는 future의 첫 값을 present로 가져오고, 기존 present를 past 끝에 보관한다. past가 비어 있으면 Undo할 수 없고 future가 비어 있으면 Redo할 수 없다.

## Undo 후 새 편집

AB까지 Undo한 상태에서 D를 입력하면 현재는 ABD가 된다. 일반적인 선형 이력에서는 기존 Redo 기록을 비운다.

```js
// 새 편집 후
{
  past: ['', 'A', 'AB'],
  present: 'ABD',
  future: [],
}
```

따라서 더 이상 Redo로 ABC에 갈 수 없다. 여러 편집 경로를 유지하는 별도 설계도 가능하지만 여기서는 하나의 경로를 관리한다. 값이 실제로 달라지지 않는 처리는 보통 새 편집 이력으로 기록하지 않는다.

## 저장 방식과 작업 단위는 별개

| 저장 방식 | 설명 | 고려할 점 |
| --- | --- | --- |
| 상태 스냅샷 | 해당 시점의 상태를 보관해 복원 | 이해하기 쉽지만 큰 상태의 이력이 쌓이면 메모리 비용 증가 |
| 명령·변경 기록 | 변경 작업과 되돌릴 정보를 보관 | 전체 상태 복사를 줄일 수 있지만 역연산과 예외 처리 필요 |

도형 삭제를 되돌리려면 삭제한 도형과 위치 정보 등을 보관해야 한다. 단순히 '삭제했다'는 사실만 저장하면 복원할 수 없다.

이와 별도로 **어떤 사용자 행동을 Undo 한 번으로 취급할지** 결정한다.

| 행동 | 작업 묶음 예시 |
| --- | --- |
| 연속 타이핑 | 짧은 시간의 연속 입력을 한 묶음으로 처리 |
| 붙여넣기 | 한 번의 붙여넣기를 한 작업으로 처리 |
| 도형 드래그 | 시작부터 종료까지 한 작업으로 처리 |
| 그림 그리기 | 펜을 누른 뒤 뗄 때까지의 한 획 |
| 여러 도형 삭제 | 선택된 도형 삭제 전체를 한 작업으로 처리 |

드래그 화면은 매 프레임 갱신하더라도 이력에는 완료된 이동 한 번만 남길 수 있다. 매 프레임을 이력으로 저장하면 되돌리기를 여러 번 해야 하고 메모리도 낭비할 수 있다. 스냅샷 방식에서도 획 하나를 묶을 수 있고, 명령 방식에서도 같은 작업 단위를 사용할 수 있다.

## React 상태와 메모리

과거 상태 객체를 현재 상태와 공유한 채 직접 수정하면 과거 이력까지 바뀔 수 있다. 새 상태는 불변성을 지켜 만들고, 보관 중인 객체를 나중에 수정하지 않는다. 매번 전체 객체를 깊은 복사해야만 하는 것은 아니며 불변 자료구조의 구조적 공유를 활용할 수도 있다.

커서 깜빡임이나 로딩 상태 등 모든 UI 변경을 편집 이력에 넣을 필요는 없다. 되돌릴 문서 데이터와 필요한 선택·커서 정보를 정하고, 이력 개수나 메모리 사용 한도도 고려한다.

자동 저장된 문서를 Undo한다면 변경된 현재 상태를 서버에 다시 저장할지 정책을 정해야 한다. 로컬 상태를 되돌리는 것만으로 이미 수행된 네트워크 작업이 자동 취소되지는 않는다. 협업 편집의 Undo는 다른 사용자의 변경도 고려해야 하므로 단순한 전역 스냅샷 복원보다 복잡하다.

## 간단한 실습 방향

메모 입력창과 Undo·Redo 버튼을 만들고 past, present, future를 화면에 표시한다. 초기 실습에서는 입력 변화마다 이력을 남기고, 이후 연속 입력을 묶는 방식으로 개선할 수 있다. Undo 후 새 입력 시 future가 비워지는지와 이력이 없을 때 버튼이 비활성화되는지 확인한다.

## 말로 설명하기

편집기의 Undo와 Redo는 이전 상태나 변경 기록을 보관해 문서 상태를 되돌리고 다시 적용하는 기능입니다. 간단하게 past, present, future로 나누어 Undo 시 현재를 future로 옮기고 과거 값을 복원합니다. Undo 후 새 편집을 하면 기존 future는 비웁니다. 저장 방식으로는 스냅샷이나 명령 기록이 있고, 사용자 관점에서는 드래그 한 번이나 펜 획 하나를 하나의 작업으로 묶는 것이 중요합니다.
