# 비활성 탭의 생명주기와 메모리 회수

탭을 오래 열어 두었다가 돌아왔을 때 기존 화면이 이어질 수도 있고 페이지가 다시 로드될 수도 있다. 브라우저가 백그라운드 실행을 제한한 것인지, 페이지를 폐기해 메모리를 회수한 것인지 구분한다.

## 숨김, 동결, 폐기

| 상태 | 백그라운드 동작 | 복귀 시 |
| --- | --- | --- |
| Hidden (숨김) | 페이지는 남아 있지만 타이머 실행 빈도 등이 제한될 수 있다. | 기존 화면을 이어서 사용한다. |
| Frozen (동결) | 타이머 콜백 등 중단 가능한 작업의 실행을 멈추고 페이지 상태를 보존한다. | 기존 페이지가 재개되고 메모리의 React state도 유지된다. |
| Discarded (폐기) | 탭은 목록에 남지만 브라우저가 페이지를 폐기해 메모리를 회수한다. | 문서가 다시 로드되므로 기존 메모리상의 React state는 사라진다. |

숨김, 동결, 폐기가 정해진 시간에 순서대로 일어나는 것은 아니다. 브라우저, 기기, 설정과 메모리 상황에 따라 달라진다. 타이머를 늦게 실행하는 것은 주로 실행 비용을 줄이는 처리이고, 페이지 폐기는 메모리를 확보하는 처리다. [Chrome 페이지 생명주기](https://developer.chrome.com/docs/web-platform/page-lifecycle-api?hl=ko)

## 상태 감지와 복귀 처리

- `visibilitychange`에서 `document.visibilityState`를 읽어 화면에 보이는지 확인할 수 있다. 숨김 알림이 폐기 알림을 의미하지는 않는다.
- 지원 환경에서는 `freeze`와 `resume` 이벤트로 동결과 재개를 관찰할 수 있다. 이 이벤트를 모든 브라우저에서 사용할 수 있다고 가정하지 않는다.
- Chrome의 지원 환경에서는 페이지 로드 시 `document.wasDiscarded`로 이전 문서의 폐기 여부를 확인할 수 있다. 폐기 전에 실행되는 알림은 아니다.

예를 들어 주문 대시보드의 기존 화면이 재개되더라도, 사용자가 탭을 보지 않는 동안 서버의 주문이나 재고가 바뀌었을 수 있다. 다시 보일 때 마지막 조회 시각을 확인해 필요하면 재조회하고, 끊긴 연결은 재연결한다. 타이머 화면은 콜백이 실행된 횟수 대신 기준 시각과 현재 시각의 차이로 갱신한다.

## 초안은 미리 저장한다

폐기 직전에 저장 코드를 실행할 기회가 보장되지 않는다. 중요한 입력값은 작성 중에 로컬 저장소나 서버에 저장하고, 페이지 초기화 시 읽어서 복원한다. 숨김 전환을 보조 저장 시점으로 쓸 수 있지만 마지막 이벤트 한 번에 의존하지 않는다.

React Activity는 앱 안에서 숨겨진 UI의 상태를 보존하는 기능이다. 페이지 자체가 폐기되면 Activity 안의 상태도 사라진다. bfcache는 뒤로·앞으로 탐색 시 기존 페이지를 복원하는 최적화다. 탭 폐기 뒤 재로드와는 구분한다.

## 실습 방법

1. 입력창과 타이머를 만든 뒤 `visibilitychange`에서 표시 상태를 기록한다.
2. 테스트 탭을 전환해 숨김과 복귀를 관찰한다.
3. Chrome의 `chrome://discards`에서 테스트 탭을 폐기한 뒤 복귀한다. 메모리에만 둔 입력과 저장소에서 복원한 입력을 비교한다.

위는 실습 절차이며 실제 브라우저 테스트 결과는 아니다.

## 면접에서 설명하기

비활성 탭은 타이머가 제한되거나 동결될 수 있지만, 그동안 페이지의 메모리 상태는 남아 있을 수 있습니다. 브라우저가 탭의 페이지를 폐기해 메모리를 회수하면 복귀 시 다시 로드되고 저장하지 않은 React state는 사라집니다. 그래서 사용자 초안은 작성 중에 저장하고, 서버 데이터는 화면 복귀 시 최신성을 확인합니다.
