# Claude Code Mods: 이벤트와 UI를 확장하는 플러그인

## 개념

Mod는 JavaScript·TypeScript 이벤트 핸들러로 Claude Code의 화면과 동작을 확장하는 플러그인이다. Plan mode 같은 실행 모드와 구분한다.

프롬프트 제출, 도구 호출, 턴 종료와 UI 표시 등의 이벤트가 발생하면 등록한 함수가 실행된다. 세션 안에서 상태를 유지하며 사용량 표시, 도구 호출 확인, 변경 검토 화면 같은 기능을 만들 수 있다. [공식 문서](https://code.claude.com/docs/en/plugins/mods/overview)

## 활용 사례

| 예제 | 역할 |
| --- | --- |
| Token Weather | 컨텍스트 사용량을 읽고 기록해 표시 |
| Blast Radius | 위험한 명령을 보류하고 예상 영향과 확인 화면 제공 |
| Replay Theater | 한 턴에서 발생한 파일 변경을 순서대로 검토 |

이벤트에서 사용량 정보를 읽거나 호출 횟수를 세는 작업은 코드로 처리할 수 있다. 이런 표시 기능에 매번 LLM 추론이 필요한 것은 아니다. 다만 Mod가 모델을 호출하는 기능을 구현한다면 별도의 모델 사용이 발생할 수 있다.

```text
도구 호출 이벤트 발생
-> 등록한 Mod 핸들러 실행
-> 횟수 기록 또는 호출 내용 검사
-> 구현에 따라 실행 계속, 수정 또는 보류
-> UI 갱신
```

## Skill, MCP, 설정 Hook과 비교

| 방식 | 주된 역할 |
| --- | --- |
| Skill | 모델이 읽을 작업 방법과 지침 제공 |
| MCP | 외부 도구와 데이터 연결 |
| 설정 Hook | 이벤트에 셸 명령, HTTP 요청 등의 처리 연결 |
| Mod | Claude Code 내부에서 함수로 이벤트와 UI 처리 |

Skill은 모델의 판단에 영향을 주고, Mod는 해당 이벤트가 실행되는 과정에 코드로 직접 개입한다. 설정 Hook도 실행 시점에 개입할 수 있으므로 실행 제어가 Mod만의 기능이라고 이해하지 않는다.

예를 들어 Skill에 '삭제 전에 확인하라'고 쓰면 모델이 지침을 읽고 확인하도록 유도한다. 확인용 Mod는 도구 호출 이벤트를 받아 실행을 보류하고 사용자에게 영향을 보여주는 로직을 구현할 수 있다.

## 확인용 Mod의 한계

명령 문자열을 검사하는 Mod는 자신이 인식하는 패턴 안에서 동작한다. 직접적인 삭제 명령을 찾더라도 다음처럼 스크립트 내부에서 삭제하는 경우는 놓칠 수 있다.

```bash
./cleanup.sh
```

따라서 Blast Radius 같은 확인용 Mod를 완전한 권한 시스템으로 취급하지 않는다. 반드시 제한해야 하는 접근은 실행 환경의 권한과 격리 설정도 함께 고려해야 한다.

Mod 자체도 사용자 권한으로 실행되는 코드다. 공식 문서에 따르면 파일 읽기·쓰기, 프로세스 실행과 네트워크 요청이 가능하고 Mod 자체는 샌드박스로 격리되지 않는다. Bash 도구에 적용한 샌드박스가 Mod가 직접 시작한 프로세스까지 자동으로 격리하는 것은 아니다. [실행 권한과 신뢰](https://code.claude.com/docs/en/plugins/mods/overview#decide-whether-to-trust-a-mod)

화면 표시용 Mod라도 출처와 구현을 확인한다. 도구 승인을 처리하는 Mod는 권한 판단에도 영향을 줄 수 있으므로 '검사용 확장이니 안전하다'고 가정하지 않는다.

## 만들고 사용하는 흐름

Mod는 플러그인 매니페스트, 핸들러를 연결하는 설정과 JavaScript·TypeScript 코드로 구성한다. 지원하는 환경에서는 핫 리로드로 수정 결과를 확인할 수 있다. 배포와 설치는 플러그인 방식으로 진행한다.

API와 지원 환경은 버전에 따라 바뀔 수 있으므로 실제 구현 시 공식 문서와 해당 버전의 타입 선언을 확인한다. 이 학습에서는 설치나 Mod 실행을 진행하지 않았다.

## 면접용 설명

Claude Code Mod는 이벤트 핸들러를 사용해 에이전트 도구의 UI와 실행 흐름을 확장하는 플러그인입니다. Skill이 모델에게 작업 지침을 제공한다면 Mod는 코드로 이벤트를 관찰하거나 실행을 보류하고 화면을 갱신할 수 있습니다. 다만 검사 로직에는 한계가 있고 Mod 자체도 사용자 권한으로 실행되므로 권한 격리를 대체한다고 볼 수 없습니다.
