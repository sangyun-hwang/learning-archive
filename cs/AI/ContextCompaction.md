# 컨텍스트 압축 (Context Compaction)

긴 대화에서 작업을 이어가는 데 필요한 정보를 남기면서, 모델에 전달하는 입력 문맥을 줄이는 방식이다. 대화창에 보이는 기록, 저장된 대화 원문, 모델이 이번 요청에서 받는 입력은 서로 구분한다.

## 무엇을 압축하는가

대화가 길어지면 오래된 메시지의 일부를 요약하고, 최근 대화나 아직 필요한 도구 결과는 원문으로 남길 수 있다. 목표, 확정한 결정, 사용자 제약, 남은 작업처럼 다음 행동에 영향을 주는 정보는 우선 보존한다.

```text
목표: React Activity 학습 문서 보강
확정: 탭 전환 시 상태 보존과 Effect 정리 사례를 넣는다.
제약: 기존 파일은 삭제하지 않는다.
남은 작업: 기존 문서 확인, 변경 검증, 푸시
```

압축을 하면 긴 세션을 이어가는 데 필요한 입력을 줄일 수 있지만, 요약은 원문과 같지 않다. 위 예시에서 파일 삭제 금지 조건이 빠지면 에이전트가 불필요하다고 판단한 문서를 제거하는 등 사용자의 의도와 다른 변경을 할 수 있다.

## 압축, 지속 메모리, 세션 검색

| 기능 | 역할 | 예시 |
| --- | --- | --- |
| 컨텍스트 압축 | 현재 세션에 넣는 입력을 줄임 | 결정과 남은 작업을 요약 |
| 지속 메모리 | 여러 세션에서 반복해서 쓸 정보를 보관 | 사용자가 짧은 예제를 선호한다는 사실 |
| 세션 검색 | 현재 문맥에 빠진 이전 대화의 내용을 찾아옴 | 합의한 파일 경로나 요청 문구 확인 |

압축 자체가 저장된 원문의 삭제를 뜻하지는 않는다. 예를 들어 [Hermes의 in-place compaction](https://hermes-agent.nousresearch.com/docs/developer-guide/context-compression-and-caching#in-place-compaction-single-stable-session-id)은 같은 세션 ID에서 활성 문맥을 줄이고 압축 전 기록은 검색 가능하게 남긴다. 원문을 보존하거나 찾는 방법은 도구마다 다르다.

요약에서 정확한 파일 경로가 빠졌다면 세션 검색으로 원래 대화를 찾아 확인한다. 실제 경로가 지금도 유효한지는 저장소에서 확인한다. 중요한 제약도 요약만으로 확실하지 않으면 원문이나 프로젝트의 기록으로 돌아간다.

## 면접에서 설명하기

> 컨텍스트 압축은 긴 대화에서 모델에 전달하는 입력을 줄이면서 작업을 이어갈 수 있도록 목표와 결정 사항을 남기는 방식입니다. 저장된 대화 원문을 삭제하는 것과는 다릅니다. 요약에서 파일 경로나 사용자 제약이 빠질 수 있으므로 중요한 세부 정보는 세션 검색이나 작업 기록으로 확인합니다.
