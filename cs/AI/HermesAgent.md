# Hermes Agent

## 개념

Hermes Agent는 Nous Research가 만든 오픈소스 자율 AI 에이전트다. 공식 사이트에서는 서버나 개인 기기에 설치해 지속적으로 실행되는 개인 AI 에이전트로 소개한다.

단순 챗봇이나 코파일럿이라기보다, 로컬 메모리, 도구 실행, 스킬 시스템, 메시징 게이트웨이, 예약 자동화 기능을 가진 자체 호스팅 agent에 가깝다.

```txt
챗봇:
대화형 응답 중심

코파일럿:
특정 작업 보조 중심

Hermes Agent:
기기에 설치되어 지속 실행되고, 메모리와 도구를 사용해 반복 작업을 수행하는 개인 에이전트
```

## 지속 실행되는 개인 AI 에이전트로 보는 이유

Hermes Agent는 한 번의 대화로 끝나는 도구가 아니라, 서버나 기기에서 계속 실행될 수 있는 agent를 지향한다.

특징은 다음과 같다.

- 로컬에 메모리를 저장한다.
- 사용자의 선호, 프로젝트, 환경을 기억할 수 있다.
- 메시징 플랫폼을 통해 계속 지시를 주고받을 수 있다.
- 예약 작업을 실행할 수 있다.
- 문제 해결 과정에서 reusable skill을 만들 수 있다.

즉 사용자가 매번 모든 맥락을 다시 설명하지 않아도, agent가 이전 정보와 작업 흐름을 유지하면서 계속 도와주는 형태를 목표로 한다.

## Persistent Memory

지속 메모리는 세션이 바뀌어도 사용자 정보, 프로젝트 정보, 환경 설정, 선호도를 기억하는 기능이다.

이 기능이 있으면 다음이 가능해진다.

- 사용자 맞춤 응답
- 프로젝트 맥락 유지
- 반복 작업 흐름 유지
- 이전 문제 해결 방식 재사용

예를 들어 agent가 특정 프로젝트의 구조, 사용자가 선호하는 방식, 자주 사용하는 명령을 기억하면 다음 작업을 더 빠르게 진행할 수 있다.

## Hermes Gateway

Hermes Gateway는 여러 메시징 플랫폼과 Hermes Agent를 연결하는 역할을 한다.

공식 사이트 기준으로 Hermes는 Telegram, Discord, Slack, WhatsApp, Signal, CLI 같은 채널을 하나의 gateway process로 연결할 수 있다고 설명한다.

관계를 구분하면 다음과 같다.

```txt
Hermes Agent:
메모리, 도구, 스킬, 자동화를 가진 핵심 에이전트

Hermes Gateway:
여러 메시징 플랫폼과 Hermes Agent를 연결하는 통로
```

즉 Hermes Gateway는 Hermes Agent 전체가 아니라, 여러 채널에서 agent와 대화하고 지시를 전달하기 위한 연결 계층이다.

## Skill System

Hermes Agent는 문제를 해결하면서 재사용 가능한 skill 문서를 만들 수 있다고 설명한다.

이것은 같은 문제나 비슷한 작업을 다음에 더 효율적으로 처리하기 위해, 해결 과정과 절차를 skill 형태로 남기는 기능으로 볼 수 있다.

예를 들어 사용자가 반복적으로 비슷한 분석이나 자동화를 요청한다면, agent는 그 절차를 skill로 정리해 다음 작업에서 재사용할 수 있다.

```txt
문제 해결
-> 절차와 도구 사용 방식 정리
-> reusable skill 생성
-> 다음 유사 작업에서 재사용
```

## Messaging and Automation

Hermes Agent는 CLI뿐 아니라 여러 메시징 플랫폼과 연결될 수 있다.

이 구조는 사용자가 특정 앱 안에 들어가지 않아도, 평소 사용하는 메신저를 통해 agent에게 지시하고 결과를 받을 수 있게 한다.

또한 cron 기반 예약 자동화 기능을 통해 반복 작업을 무인으로 실행할 수 있다.

예시:

- 일일 보고서
- 주간 점검
- 백업
- 반복 리서치
- 프로젝트 상태 확인

## Self-hosting과 Local Data

Hermes Agent는 자체 호스팅과 로컬 데이터 저장을 강조한다.

장점은 다음과 같다.

- 외부 SaaS 장애에 덜 의존한다.
- 데이터가 로컬에 남아 개인정보 통제가 쉬워질 수 있다.
- 텔레메트리나 추적 없이 사용할 수 있다.
- 운영 환경을 직접 통제할 수 있다.

하지만 책임도 함께 생긴다.

- 설치와 업데이트를 직접 관리해야 한다.
- 장애 발생 시 직접 대응해야 한다.
- 로컬 데이터 백업과 보안을 관리해야 한다.
- 연결한 메신저, API key, 모델 provider credential을 안전하게 관리해야 한다.

즉 자체 호스팅은 자유도와 통제권을 주지만, 운영 책임도 사용자에게 온다.

## 주의할 점

Hermes Agent 같은 지속 실행 agent는 권한 관리가 중요하다.

메모리, 도구 실행, 메시징 gateway, 예약 자동화가 결합되면 편리하지만, 잘못 설정하면 민감 정보 노출이나 원치 않는 작업 실행 위험이 생길 수 있다.

따라서 다음을 고려해야 한다.

- 도구 권한 최소화
- API key와 token 관리
- 로컬 메모리 백업과 암호화
- 메시징 계정 권한 관리
- 예약 작업 검토
- 위험 작업에 대한 사용자 확인

## 정리

Hermes Agent는 로컬 메모리, 도구 실행, 스킬 시스템, 메시징 gateway, 예약 자동화를 갖춘 자체 호스팅 오픈소스 AI 에이전트다.

단순 챗봇보다 지속 실행되는 개인 agent에 가깝고, 사용자의 프로젝트와 작업 맥락을 기억하며 반복 작업을 자동화하는 것을 목표로 한다.

다만 자체 호스팅과 로컬 데이터 저장은 통제권을 주는 동시에 운영, 보안, 백업 책임도 사용자에게 요구한다.
