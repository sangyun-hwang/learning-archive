# Jev: 텍스트 생성 대신 구조화된 판단을 반환하는 AI

## 개념

Jev는 TypeSafe AI가 2026년 9월 15일 공개한 System One 모델이다. 자유로운 문장 생성보다 소프트웨어에서 반복되는 분류, 선택, 평가에 초점을 둔다. JEPA와는 다른 주제다.

TypeSafe는 새로운 아키텍처와 병렬 샘플러, RLCD(Reinforcement Learning for Calibrated Decisions)라는 학습 방식을 사용한다고 설명한다. 여기서는 공개된 제품 동작과 활용 관점을 정리하며, 내부 구조를 직접 검증했다는 의미는 아니다. [공식 발표](https://typesafe.ai/blog/introducing-system-one-models-and-jev)

## LLM과 비교하기

| 관점 | 일반적인 생성형 LLM | Jev |
| --- | --- | --- |
| 대표 작업 | 설명, 요약, 코드와 답변 작성 | 분류, 선택, 점수 평가 |
| 출력 | 자유로운 텍스트 또는 구조화된 값 | 정해진 타입의 판단과 확률 등 |
| 고객 문의 예시 | 답변 초안 작성 | 담당 부서 분류와 긴급도 평가 |

LLM도 JSON이나 스키마에 맞는 구조화된 출력을 제공할 수 있다. 따라서 차이는 JSON 출력 가능 여부가 아니라 **어떤 작업을 수행하도록 설계하고 최적화했는가**에 있다.

Jev는 문장을 토큰 단위로 생성하는 대신 판단 결과를 반환하는 방식에 초점을 둔다. 그렇다고 같은 작업에서 입력 토큰이 항상 적거나 모든 작업이 더 빠르다고 일반화할 수는 없다. 비용과 지연 시간은 입력 크기, 질문 구성, 비교 모델과 실행 환경을 맞춰 평가해야 한다.

## 서비스 적용 흐름

API에는 판단할 자료인 state와 타입이 정해진 questions를 전달한다. 선택형 질문, 점수 평가, 명제의 참 여부에 대한 확률 판단 등을 사용할 수 있다. [공식 API 문서](https://api.typesafe.ai/redoc)

아래는 고객 문의 처리의 개념 예시이며 실제 API 요청 스키마는 아니다.

```text
상황: 결제가 두 번 됐는데 주문은 하나만 보인다는 문의

질문:
- 담당 부서는 결제 / 배송 / 계정 중 어디인가?
- 긴급도는 어느 정도인가?
- 사람의 검토가 필요한가?

문의와 필요한 주문 정보 전달
-> Jev가 분류와 평가 수행
-> 서버가 정책에 따라 담당 팀 배정
-> 필요하면 LLM이 답변 초안 작성
-> 담당자가 확인
```

Jev가 분류하고 LLM이 문장을 작성하는 식으로 역할을 나눌 수 있다. 실제 배정이나 환불 실행은 모델이 아니라 연결된 애플리케이션 코드가 수행한다.

## 타입이 맞는 것과 판단이 맞는 것은 다르다

```text
허용된 값인 '결제'를 반환
!= 실제로 결제 팀에 보내야 하는 문의라는 보장
```

공식 발표의 환각 방지 주장을 '항상 옳다'는 뜻으로 이해하면 안 된다. 출력 스키마를 벗어나지 않는 것과 내용이 사실에 맞는지는 별개다. 입력에 필요한 정보가 없거나 분류 기준이 모호하면 판단도 틀릴 수 있다.

2026년 9월 공개된 Jev 평가 프리프린트도 작업별 성능 차이를 보고한다. 이진 확률을 일괄적으로 0.5 기준으로 나누기보다 데이터에 맞춰 임계값을 조정했을 때 개선되는 사례가 있었다. 특정 버전과 평가 데이터에 대한 결과이므로 모든 서비스에 그대로 적용할 수는 없다. [평가 논문](https://arxiv.org/abs/2609.37647)

확률 보정(calibration)은 예를 들어 80%라고 평가한 유사한 예측들이 실제로도 대략 80% 맞는지를 보는 개념이다. 개별 예측이 반드시 맞는다는 보증이 아니며, 실제 서비스 데이터에서도 확인해야 한다.

## 서버의 책임은 유지된다

모델이 환불 가능성이 높다고 판단해도 서버는 다음을 별도로 검사한다.

- 요청한 사용자가 해당 주문의 소유자인가?
- 정책상 환불 가능한 상태와 금액인가?
- 사용자가 실제로 환불 실행을 요청했는가?
- 이미 처리한 요청이 아닌가?

이 검사는 모델이 틀릴 수 있기 때문만이 아니다. **판단의 정확성과 실행 권한은 서로 다른 문제**다. 문의 요약만 요청했는데 모델이 환불이 타당하다고 판단했다고 해서 환불 실행까지 승인된 것은 아니다.

불확실하거나 영향이 큰 작업은 사람의 검토로 넘기고, 모델 결과를 권한 검사나 업무 규칙의 대체물로 사용하지 않는다. 구조화된 출력만으로 프롬프트 인젝션이나 잘못된 실행까지 해결된다고 가정하지 않는다.

## 면접용 요약

Jev는 자유로운 답변 생성보다 분류와 평가 같은 구조화된 판단에 최적화된 AI 모델입니다. LLM도 JSON을 반환할 수 있으므로 단순한 출력 형식이 아니라 설계 목적과 실행 효율을 기준으로 구분합니다. 정해진 타입의 출력도 잘못된 판단일 수 있고, 판단이 맞더라도 실행 권한을 의미하지 않으므로 서버의 검증과 권한 관리는 유지해야 합니다.
